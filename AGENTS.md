# harnessctl agent guide

`start.sh` is the canonical, self-contained Bash launcher for Claude Code,
Codex, tmux, and Herdr. Work directly on `main`, push only to Forgejo `origin`,
and preserve unrelated or concurrent edits.

Every repository change belongs to an owning bead. This workspace uses bead-rs
(`bead`). Before editing, find or create the owning bead; record material
decisions, affected paths, actual verification, release/deployment evidence,
and skipped checks. Flush the checkpoint when needed.

## Repository map

- `start.sh`: canonical launcher, embedded public key, manifest verifier, and
  `start` CLI.
- `scripts/install.sh.in`: canonical installer wrapper.
- `install.sh`, `start.sh.version`: generated by
  `python3 scripts/release.py generate`; never edit directly.
- `scripts/release.py`: generation, parity, release preparation, verification,
  fixture signing, and immutable archive creation.
- `tests/`: offline signed fixtures, interface/configuration/diagnostic/update
  tests, and real unprivileged tmux runtime tests.
- `keys/release-signing.pub`: public key only. Private production keys remain
  non-exportable in OpenBao Transit.
- `releases/vVERSION/`: immutable signed release artifacts.
- `docs/operations/releasing.md`: current production release runbook.

## Change recipes

- CLI/resume/workdir: edit `start.sh`, update `usage`, README examples, and
  `tests/start-sh-interface-test.sh`; run the real tmux test when execution
  context changes.
- Config/default: edit `start.sh`, the README configuration table,
  `tests/configuration-test.sh`, and security docs when permissions change.
- Doctor: preserve `harnessctl-doctor-v1` compatibility, update
  `tests/doctor-test.sh`, and document any new stable check.
- Trust/updater: edit the verifier in `start.sh`, regenerate the installer, and
  cover every failure stage in `tests/start-sh-self-update-test.sh` and
  `tests/install-update-test.sh`.
- Installer wrapper: edit `scripts/install.sh.in`, then regenerate.
- Release tooling: preserve forward-only versions and archive immutability;
  update `tests/release-test.sh`.
- Bootstrap bridge: use `scripts/adopt-bootstrap.sh` with a clean signed source;
  it must preserve bootstrap's distribution URL while selecting harnessctl for
  launcher updates.

## Invariants

- Resume IDs remain one inert argument through update re-exec and tmux quoting.
- `-C`, configured workdir, and caller-directory defaults behave identically in
  bare shell, tmux, and Herdr.
- Routine update failures preserve installed bytes and continue ordinary
  launch; explicit `start update` fails.
- Source checkouts never self-update in place.
- Generated installer trust code matches the launcher exactly.
- Signed release directories are immutable. Roll back behavior only through a
  higher semantic version.
- Key rotation overlaps old and new trust anchors before the signer switches.
- JSON diagnostic changes are additive within a schema version.

## Verification and delivery

Run a focused test while iterating, then `scripts/check.sh` for the complete
local gate. It covers Bash syntax, generated parity, offline signed updater and
installer cases, CLI/configuration/doctor behavior, release fixtures, and real
tmux runtime as an unprivileged user. When run as root it uses `runuser` and a
disposable `/tmp` directory. Test artifacts otherwise use the physical scratch
directory, never the repository.

Publish only through declarative-config's protected
`harnessctl-release-sign` WorkflowTemplate in `iad-ci`. Do not add GitHub
Actions, configure client-side mirror pushes, mutate ArgoCD-managed resources,
expose credentials, or sign production artifacts with a local private key.
Follow `docs/operations/releasing.md`, verify Forgejo and GitHub convergence,
and record the exact release commit, workflow, checks, and rollout on the bead.

Done means canonical and generated files agree, relevant documentation and
tests cover the behavior, the complete gate passes, precise paths are committed
on `main` and pushed to Forgejo, and any user-visible deployment is backed by a
verified signed release.
